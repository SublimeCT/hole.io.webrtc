## 道具系统

### 通用规则

- 开局立即刷新与玩家数相同的随机道具点，之后每 `60s` 再刷新相同数量。
- 黑洞范围覆盖道具点时立即拾取并发动；判定、积分和物体状态由权威模拟计算。
- 地图道具点和洞心持续标识均为固定 `200px` HTML emoji，不随距离、视角或黑洞尺寸缩放。
- 地图道具点按玩家位置指示方式投影，位于视野外时贴屏幕边缘显示。
- 持续效果标识在半透明与全透明之间循环。

## 联机协议

协议类型的唯一真源是 `packages/shared/protocol`（client 与 server 直接 `import`，禁止两端各维护一份）。下表只描述消息清单与关键语义，完整字段定义以源码为准。信令服务地址 `wss://<host>/ws`，单条 WSS 通道同时管房间管理、信令、生命周期。

### 房间状态机

`lobby → connecting → playing → lobby`，房间可循环多局：

| 状态         | 服务端行为                                                                                       |
| ------------ | ------------------------------------------------------------------------------------------------ |
| `lobby`      | 从建房或上一局结束开始 `180s` 倒计时；所有 entered 玩家 ready 后 host 才能开始建连；超时销毁房间 |
| `connecting` | 最长 `30s`；只转发 host↔guest SDP/ICE；超时退回 lobby、清空 ready 并重启 `180s` 倒计时           |
| `playing`    | 固定 `180s`；WSS 保持，客户端消息仅接受 heartbeat；计时结束后所有人必须重新 `enter-room`         |

客户端每 `4s` 发送 application heartbeat。任一 guest 超过 `8s` 只被移出；host 超过 `8s` 解散房间。全局最多 `20` 个活跃房间。

### WSS 消息（client → server）

| type                                      | 关键字段                        | 说明                                             |
| ----------------------------------------- | ------------------------------- | ------------------------------------------------ |
| create-room                               | `profile`                       | 建房并成为 host                                  |
| enter-room                                | `roomCode`, `profile`           | 首次加入或局后重新进入                           |
| set-ready                                 | `ready`                         | lobby ready 状态                                 |
| begin-connection                          | —                               | host 在所有 entered 玩家 ready 后进入 connecting |
| signal-offer / signal-answer / signal-ice | `toPeerId` + 严格结构化 SDP/ICE | 仅 connecting 的 host↔guest 转发                 |
| start-match                               | —                               | host 确认全部 WebRTC 连接后进入 playing          |
| heartbeat                                 | `clientTime`                    | 所有状态每 `4s` 发送                             |
| leave-room / close-room                   | —                               | 离开；host 可主动解散                            |

### WSS 消息（server → client）

| type                                      | 说明                                     |
| ----------------------------------------- | ---------------------------------------- |
| connected                                 | 分配 peerId，并告知 `4s/8s` 心跳参数     |
| room-created / room-entered               | 返回完整 room state 与 TURN 临时凭据     |
| room-state / connection-started           | 广播 roster、entered、ready 和房间计时   |
| signal-offer / signal-answer / signal-ice | 将 `toPeerId` 改写为 `fromPeerId` 后转发 |
| match-started / match-ended               | 服务端固定对局计时和重新入房截止时间     |
| room-closed / heartbeat-ack / room-error  | 生命周期、心跳和统一错误                 |

房间码为 `^[A-HJ-NP-Z2-9]{6}$`。有效格式但不存在的房间尝试按真实客户端 IP 记录：连续 `5` 次临时封禁全部访问 `5m`，累计 `10` 次永久封禁；成功进入真实房间只重置连续次数。不可用、已满或非 lobby 对外统一 `ROOM_UNAVAILABLE`，不暴露房间枚举信息。所有 WSS message 使用 strict runtime schema，禁止额外字段；用户名为 NFKC 后 `2–10` 个 Unicode code point，颜色为 `#RRGGBB`，语言为项目十种 i18n 枚举，平台字符受限且最长 `20`。

### TURN 中继

打洞失败走 coturn auth-secret 临时凭据。server 在建房/入房结果中返回 `turn { username, credential, ttl, uris }`；coturn 验证 STUN/TURN 协议和认证，DTLS 内的游戏消息由 peer 端共享协议校验。配置见 `infra/docker-compose.yml` 与 `infra/coturn/turnserver.conf`。

### P2P 星型拓扑

每个 guest 只与 host 建一条 `RTCPeerConnection`（非 mesh）。WSS 在 playing 期间必须保持，用于 application heartbeat 和服务端房间计时；游戏数据永不经 WSS 转发。

### DataChannel 实时同步（host ↔ guests，不经信令服务）

| 数据                                | 关键语义                                                                        | channel    |
| ----------------------------------- | ------------------------------------------------------------------------------- | ---------- |
| InputPacket guest→host ~30Hz        | matchId、输入 seq、归一化 direction、clientTime、abilities；不含位置/分数       | unreliable |
| StateDeltaSnapshot host→guest ~10Hz | snapshotSeq、hostTick、base/worldRevision、全部玩家当前状态和本次改变的世界对象 | unreliable |
| 世界事件与开始/结束                 | 物体吞噬、玩家阵亡/复活、道具变化、match start/end                              | reliable   |
| resync-request / checkpoint chunks  | revision 不连续时请求；分块传输完整可观察世界                                   | reliable   |

普通快照 `snapshotSeq` 允许断层；只有接收端 `worldRevision` 与增量 `baseWorldRevision` 不匹配才请求重同步。checkpoint 在相同 mapId/mapRevision/seed 基线上包含全部玩家、道具、临时实体、活跃物体以及所有偏离地图初始状态的物体；仍为初始状态的物体不传。checkpoint 不附加在 unreliable 普通快照中，全部分块到齐后原子应用。

同一 host tick 内多人满足吞噬同一普通物体时，物体只移除一次，但可同时给所有满足者计分；任何涉及玩家阵亡的竞态只采用 host 最先处理并广播的权威结果。

| 项                           | 默认值         |

| 全局并发连接上限             | `100`          |
| 单 IP 并发连接上限           | `5`            |
| 全局房间数上限               | `20`           |
| 房间人数上限                 | `5`            |

后端使用 PostgreSQL（用户和数据库名均为 `holeio`）+ `pg` 连接池 + Drizzle migration；只持久化房间、对局/玩家统计骨架和 IP 封禁，不保存高频帧。配置优先级为 `process.env > .env.local > .env`，数据库密码、连接串和 TURN secret 不入库。
